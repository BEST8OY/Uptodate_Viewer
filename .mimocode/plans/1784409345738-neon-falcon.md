# Fix: FAB hidden under navigation bar overlay

## Root cause

The nav bar in `NavGraph.kt` is a custom `AnimatedVisibility` composable rendered as a sibling overlay inside a `Box`:

```
Box(fillMaxSize) {
    NavDisplay(fillMaxSize) {  // All screens including ConversationListScreen
        // ConversationListScreen's Scaffold with FAB
    }
    AnimatedVisibility(align=BottomCenter, navBar) {
        NavigationBar(...)  // Custom overlay, NOT system UI
    }
}
```

The Scaffold's FAB is positioned at the bottom of the Scaffold's coordinate space. The nav bar sits on top as a sibling. Adding `windowInsetsPadding` to the *content* inside the Scaffold pushes the list up but does NOT move the FAB — the FAB position is independent of content padding.

## Fix

Wrap the entire Scaffold in a `Box` with `padding(bottom = 80.dp)` (Material3 NavigationBar height). This shifts the whole Scaffold up, moving the FAB above the nav bar overlay.

### File: `app/src/main/java/com/clinref/app/ui/conversations/ConversationListScreen.kt`

Replace the Scaffold (and its content) with:

```kotlin
// The nav bar is a custom overlay in NavGraph, not system UI.
// Scaffold can't see it, so pad the entire Scaffold to push FAB above it.
Box(modifier = Modifier.fillMaxSize().padding(bottom = 80.dp)) {
    Scaffold(
        topBar = { /* unchanged */ },
        floatingActionButton = { /* unchanged */ }
    ) { padding ->
        // content unchanged, remove windowInsetsPadding from both branches
    }
}
```

Remove the `windowInsetsPadding(WindowInsets.navigationBars)` from both the empty-state Column and the LazyColumn — those were redundant with the outer Box padding.

Remove the unused imports: `WindowInsets`, `navigationBars`, `windowInsetsPadding` (if no longer used elsewhere in the file).

# Convert Android App to KMP (Android target only)

## Problem
Koog is KMP and publishes platform-specific artifacts (`-jvm`, `-android`, etc.). Without the KMP Gradle plugin, Android projects can't auto-select the correct variant. This causes:
- `Coroutines_jvmKt` missing class errors (R8 can't find JVM variant)
- Duplicate class errors when forcing JVM variant alongside Android variant
- Ongoing maintenance burden with shims and workarounds

## Goal
Add the Kotlin Multiplatform plugin to the existing Android-only app so KMP dependencies resolve correctly. The app remains Android-only — no iOS/desktop targets.

## What changes
1. Add `kotlin("multiplatform")` plugin
2. Convert `android.application` → `kotlin("multiplatform")` with `androidTarget()`
3. Move source files from `src/main/java/` → `src/androidMain/kotlin/`
4. Remove the `Coroutines.jvm.kt` shim (KMP resolves the correct variant automatically)
5. Keep all Android-specific deps (Hilt, Room, Compose, WebView, etc.) in `androidMain`

## What does NOT change
- No iOS/desktop targets added
- No `commonMain` source set (no shared code needed — app is Android-only)
- No Hilt restructure (stays Android-only)
- No Room restructure (stays Android-only)
- All Compose UI stays in `androidMain`

Replace the existing dead-code `data/ai/RoomChatHistoryProvider.kt` with a real implementation:

```kotlin
package com.clinref.app.data.ai

import ai.koog.agents.chatMemory.feature.ChatHistoryProvider
import ai.koog.prompt.message.Message
import com.clinref.app.data.local.dao.MessageDao
import com.clinref.app.data.local.entity.MessageEntity
import kotlinx.serialization.encodeToString
import kotlinx.serialization.json.Json
import java.util.UUID
import javax.inject.Inject
import javax.inject.Singleton

@Singleton
class RoomChatHistoryProvider @Inject constructor(
    private val messageDao: MessageDao
) : ChatHistoryProvider {

    private val json = Json { ignoreUnknownKeys = true }

    override suspend fun store(conversationId: String, messages: List<Message>) {
        // Clear existing messages for this conversation, then save new ones
        messageDao.deleteByConversation(conversationId)
        for (msg in messages) {
            val entity = MessageEntity(
                id = msg.id.ifEmpty { UUID.randomUUID().toString() },
                conversationId = conversationId,
                role = messageRoleToString(msg),
                content = extractText(msg),
                timestamp = System.currentTimeMillis()
            )
            messageDao.insert(entity)
        }
    }

    override suspend fun load(conversationId: String): List<Message> {
        return messageDao.getMessagesList(conversationId).map { entity ->
            // Convert MessageEntity back to Koog Message
            // The exact mapping depends on Koog's Message type structure
            stringToMessage(entity.role, entity.content)
        }
    }

    private fun messageRoleToString(msg: Message): String = when (msg) {
        is Message.System -> "system"
        is Message.User -> "user"
        is Message.Assistant -> "assistant"
        else -> "unknown"
    }

    private fun extractText(msg: Message): String = when (msg) {
        is Message.System -> msg.parts.joinToString("\n") { it.text }
        is Message.User -> msg.parts.joinToString("\n") { /* extract text from parts */ "" }
        is Message.Assistant -> msg.parts.joinToString("\n") { /* extract text from parts */ "" }
        else -> ""
    }

    private fun stringToMessage(role: String, content: String): Message {
        // Convert stored role+content back to Koog Message types
        return when (role) {
            "user" -> Message.User(parts = listOf(MessagePart.Text(content)))
            "assistant" -> Message.Assistant(parts = listOf(MessagePart.Text(content)))
            "system" -> Message.System(parts = listOf(MessagePart.Text(content)))
            else -> Message.User(parts = listOf(MessagePart.Text(content)))
        }
    }
}
```

**NOTE**: The `Message` type hierarchy and `MessagePart` types must be verified against `ai.koog.prompt.message` at compile time. The exact constructor signatures may differ.

## 2. Wire SafetyValidator into the Real Flow

### Problem
`SafetyValidator` has 414 lines of tests but is never called from any production code path.

### Design

The validator runs inside `KoogAgentFactory`'s `onAgentCompleted` event handler, using data accumulated by `TurnContextAccumulator` during the agent run.

### Flow

```
onToolCallStarting → accumulator.onToolCallStarting(name, args)
onToolCallCompleted → accumulator.onToolCallCompleted(name, result, success)
onAgentCompleted → 
    val turnCtx = accumulator.buildTurnContext(result)
    val validation = safetyValidator.validate(turnCtx)
    streamingManager.onCompleted(result, validation)
    accumulator.reset()
```

### Files to modify

- **`domain/ai/KoogAgentFactory.kt`** — event handler wiring (described above)
- **`domain/ai/TurnContextAccumulator.kt`** — new file (described above)
- **No changes to `SafetyValidator.kt`** — it's already correct

### TurnContext building logic

`buildTurnContext(answer)` parses accumulated data:
- `toolCalls`: from accumulated `ToolCallRecord` list
- `answer`: the agent's final result string
- `citations`: parsed from answer text (regex for topic/section citations in the answer)
- `toolResults`: raw text from each tool call's result
- `fetchedSections`: parsed from `getTopicSectionText` results (extract topic/section metadata)
- `graphicIds`: from `getGraphicInfo` calls
- `sectionWarnings`: from `[WARNING]` markers in `getTopicSectionText` results
