# Fix: back animation + predictive back

## 1. Symmetric slide transitions

Forward pushes slide right-to-left. Back should slide left-to-right.

**File**: `NavGraph.kt` — change `popTransitionSpec` and `predictivePopTransitionSpec`:

```kotlin
popTransitionSpec = {
    slideInHorizontally(motionScheme.defaultSpatialSpec()) { -it } togetherWith
        slideOutHorizontally(motionScheme.defaultSpatialSpec()) { it }
},
predictivePopTransitionSpec = {
    slideInHorizontally(motionScheme.defaultSpatialSpec()) { -it } togetherWith
        slideOutHorizontally(motionScheme.defaultSpatialSpec()) { it }
},
```

## 2. Predictive back: remove BackHandler from ContentScreen

**Root cause**: `ContentScreen.kt:137` has `BackHandler(enabled = showOutline || canGoBack)`. When `canGoBack` is true (user navigated between topics via in-article links), this handler intercepts the predictive back gesture **before** NavDisplay can render its transition preview. The handler calls `viewModel.goBack()`, which changes in-app state but doesn't pop the nav stack. NavDisplay sees no destination change, so the gesture appears to fail.

Second attempt works because `canGoBack` is now false, the handler is disabled, and the gesture reaches NavDisplay.

**Fix**: Remove the `BackHandler` from ContentScreen. All back navigation goes through NavDisplay's `onBack` callback.

**File**: `ContentScreen.kt` — remove lines 137-143 (the BackHandler block) and remove the `BackHandler` import.

**File**: `NavGraph.kt` — no changes needed. `onBack = { navigator.goBack() }` already pops ContentRoute.

**Tradeoff**: Topic-history back-navigation (going from topic B back to topic A within ContentScreen) is removed. Users navigate between topics via the outline or in-article links instead. This is the standard pattern for reference apps.
