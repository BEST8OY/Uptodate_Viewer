# Fix: Search-to-content back navigation animation

## Root Cause

When the user taps a search result, `onTopicSelected` navigates to `ContentRoute` while the `ExpandedFullScreenSearchBar` remains expanded. The search bar's full-screen overlay sits on top of the `NavDisplay` content, intercepting the back gesture and blocking the transition animation. The `NavDisplay`'s `popTransitionSpec` never fires because the overlay consumes the event first.

The existing `LaunchedEffect(searchBarState.currentValue)` at `TocScreen.kt:117-123` only collapses the search bar AFTER returning to `TocScreen` — too late to prevent the overlay from interfering.

## Fix

Collapse the search bar BEFORE navigating away. This removes the overlay so the `NavDisplay` transition can animate cleanly.

### `TocScreen.kt` — search result click handler (lines 254-260)

Wrap the navigation call in a coroutine that first animates the search bar to collapsed state:

```kotlin
// Before
modifier = Modifier.clickable {
    if (result.topicId.startsWith("Graphic-")) {
        val id = result.topicId.removePrefix("Graphic-")
        onGraphicSelected(id)
    } else {
        onTopicSelected(result.topicId)
    }
}

// After
modifier = Modifier.clickable {
    coroutineScope.launch {
        searchBarState.animateToCollapsed()
    }
    if (result.topicId.startsWith("Graphic-")) {
        val id = result.topicId.removePrefix("Graphic-")
        onGraphicSelected(id)
    } else {
        onTopicSelected(result.topicId)
    }
}
```

The `coroutineScope` is already available at line 89. `animateToCollapsed()` runs the collapse animation; the navigation call fires immediately after (in the same frame), so the overlay is removed before the back transition occurs.
